# Spring Boot React starter

A three-container web app: a React frontend, a Spring Boot backend and a Postgres
database, all running in Docker. It ships with one example feature (a list of
messages) that shows a request going from React to Spring to Postgres and back.
Replace it with your own.

There are matching TypeScript (Hono) and Python (FastAPI) starters with the same API,
the same frontend and the same `mise` tasks.

| Part     | Stack                                                                          |
| -------- | ------------------------------------------------------------------------------ |
| Frontend | React, Vite, a client generated from the API contract by `@hey-api/openapi-ts` |
| Backend  | Spring Boot 4, Java 25, Spring Data JPA, springdoc-openapi, Lombok             |
| Database | Postgres 18, migrations generated by Hibernate and applied by Flyway           |
| Tooling  | mise, Gradle, Spotless, Error Prone, oxlint, oxfmt, Docker Compose             |

```
browser -> web :5173 -> /api/* -> backend :3000 -> db :5432
           (vite in dev, nginx :8080 when deployed)
```

## Layout

```
mise.toml               Tool versions and every task you will run
compose.yaml            The deployed stack: web, backend, db
compose.override.yaml   Dev overrides: run from source, published ports
.env.example            Local settings. Copy it to .env.
backend/
  src/main/java/com/example/app/
    controller/         HTTP routes
    service/            Business logic
    dao/                The only caller of repositories, maps entities to DTOs
    dto/                Request and response shapes (these end up in the API client)
    repository/         JpaRepository interfaces with native SQL queries
    entity/             JPA entities. The source of truth for the schema.
  src/main/resources/
    application.yaml    Config, read from env vars
    db/migration/       Generated Flyway migrations. Commit these.
  openapi.json          The API contract, generated from the controllers. Commit it.
frontend/
  src/App.tsx           The page
  src/api/generated/    Client generated from the contract (not committed)
  nginx.conf            Deployed web server: serves the app and proxies /api
.agents/rules/          Extra rules for AI agents, per folder
AGENTS.md               Rules for agents and humans
```

## Getting started

You need [mise](https://mise.jdx.dev) and Docker.

```sh
mise install
cp .env.example .env
mise run setup:dev
```

`setup:dev` installs the frontend packages, generates the API client and starts every
container. Open <http://localhost:5173> and press the button.

> [!IMPORTANT]
> The app always runs in Docker. mise loads `.env`, and Docker Compose passes it into
> the containers. Running `./gradlew bootRun` or `pnpm dev` on your machine skips
> that, so the backend can't find the database and the frontend can't find the
> backend.

The frontend reloads on save. The backend does not: run `mise run dev:restart` after
changing Java code.

`mise tasks` lists every task. The ones you will use most:

| Task                                      | What it does                                                    |
| ----------------------------------------- | --------------------------------------------------------------- |
| `mise run dev:up`                         | Build and start db, backend and web in Docker                   |
| `mise run dev:down`                       | Stop every container. Database data is kept.                    |
| `mise run dev:restart`                    | Restart the backend after changing Java code                    |
| `mise run contract`                       | Regenerate `backend/openapi.json` and the frontend client       |
| `mise run db:dev:migrate:generate <name>` | Write a SQL migration from your changes to the entities         |
| `mise run db:dev:migrate:up`              | Apply pending migrations                                        |
| `mise run db:dev:migrate:status`          | Show whether the database is missing migrations                 |
| `mise run db:dev:studio`                  | Open Prisma Studio on the dev database (:5555)                  |
| `mise run db:dev:psql`                    | Open psql in the database                                       |
| `mise run check`                          | Run what CI runs: format check, lint, typecheck, contract check |
| `mise run fmt:fix`                        | Format everything                                               |
| `mise run stack:dev:up`                   | Build and run the deploy images (jar + nginx) on :8080          |

## The API contract

The controllers and DTOs are the source of truth. `mise run contract` does two things:

1. `contract:generate` boots the app briefly with the `openapi` profile, which needs no
   database, and saves the spec springdoc builds to `backend/openapi.json`. Commit
   this file.
2. `contract:client` generates a typed client with zod validators in
   `frontend/src/api/generated/`. This folder is gitignored.

`mise run check` fails if `backend/openapi.json` is out of date with the controllers.

The function names in the client come from `@Operation(operationId = ...)` on each
controller method, and type names come from `@Schema(name = ...)` on each DTO.

## The database

The entities in `backend/.../entity/` describe every table. Migrations are plain SQL
files in `backend/src/main/resources/db/migration/`.

1. Edit or add an entity.
2. Run `mise run db:dev:migrate:generate add_something`. It boots the backend once in
   a container, compares your entities to the dev database, and writes the SQL needed
   to match them into the next `V<N>__add_something.sql`.
3. Read the file. Hibernate never drops columns or tables, so write those statements
   yourself. Then run `mise run db:dev:migrate:up`.
4. Commit the entity and the migration together.

Migrations only go forward. Flyway's undo is a paid feature, so there is no down
task. Fix a mistake with a new migration, or run `mise run db:dev:reset` to start
over locally.

After pulling a teammate's migration, `mise run db:dev:migrate:status` lists every
migration and marks the ones your database is missing as `Pending`.
`mise run db:dev:migrate:up` applies them. The backend also applies pending
migrations every time it starts.

Queries are SQL too. Write them as `@Query(value = "...", nativeQuery = true)` on the
repository, as `MessageRepository` does, not as derived methods like
`findAllByOrderByCreatedAtDesc`.

`mise run db:dev:studio` opens Prisma Studio on <http://localhost:5555>, already
connected to the dev database, to browse and edit rows. For raw SQL, use
`mise run db:dev:psql`.

## Environment variables

`.env.example` lists every variable. Copy it to `.env`, which is gitignored. mise
loads `.env` for every task, and Docker Compose reads it to build each container's
environment. To add one:

1. Add it to `.env.example` and your `.env`.
2. Pass it to the `backend` service in `compose.yaml`.
3. Read it in `application.yaml` as `${MY_VAR}`, without a default.

## Making it yours

- Rename the Java package: move `backend/src/main/java/com/example/app` and update
  the `package` lines, then change `group` in `backend/build.gradle.kts`.
- Rename the project in `backend/settings.gradle.kts`, `frontend/package.json` and
  `frontend/index.html`.
- Delete the `messages` example (entity, repository, DAO, DTO, service, controller),
  run `mise run db:dev:migrate:generate remove_messages`, add the `DROP TABLE` it
  can't write, then run `mise run contract`.

## Linting and formatting

- Backend: [Spotless](https://github.com/diffplug/spotless) with google-java-format,
  and [Error Prone](https://errorprone.info/), which runs inside `javac` and fails the
  build on common bugs.
- Frontend: [oxlint](https://oxc.rs/docs/guide/usage/linter) and
  [oxfmt](https://oxc.rs/docs/guide/usage/formatter), plus `tsc` for types.

CI (`.github/workflows/ci.yml`) runs lint and format for each app on every pull
request.
